# mmd-cli 設計書 (2026-10-04)

MikuMikuDance（MMD、v9.32 x64）を、窓を前に出さずにコマンドラインから操作する道具。
主な使い手は Claude などのエージェントで、人が同じ PC で別の作業をしている間に裏で動かすことを前提にする。

正本はこのファイル。実機で確かめた事実は `spike-result-20261004.md` に分けてある。

## 1. 目的と範囲

目的は 2 つ。

1. 操作: モデル・モーション・ポーズ・音・アクセサリの読込、フレーム移動と再生、カメラ・照明、
   ボーンと表情のキー登録、プロジェクトの開く・保存、画像と AVI の書き出しを、コマンドで実行できる。
2. 確認: 操作の結果を画面の取り込み（スクリーンショット）ではなく、文字（JSON）で読み返せる。

守る制約。

- MMD の窓を前面に出さない。入力の焦点を奪わない。最小化のまま動かす。
- 操作の途中で出るダイアログを画面に見せない。
- 利用者のプロジェクトファイルを、明示の保存指示なしに書き換えない。
- MMD 本体・モデル・モーションはリポジトリに含めない（再配布できないため）。

第 1 版で作らないもの。

- pmm を一から書き出す機能（読むだけ）。
- 3D 画面上のマウス操作（ボーンのドラッグなど）。数値入力とキーフレームの読込で代える。
- MME（MikuMikuEffect）固有の操作。汎用の `menu` / `control` コマンドで触れる範囲に留める。
- 誰もログオンしていないマシンでの実行。MMD はデスクトップの無いセッションでは起動を終えない（実測）。
  SSH 越しなど別セッションからの操作は、利用者のデスクトップセッションへの中継（第 11 節）で扱う。

## 2. 方式

起動中の MMD の標準コントロール（ボタン・入力欄・コンボボックス・メニュー）へ、Windows の
窓メッセージを直接送る。MMD の主窓は 168 個の子コントロールを持ち、ID は 400〜567 で固定、
メニューの ID は 200〜302 で固定である（v9.32 は最終版なので変わらない）。

| やりたいこと | 手段 |
| --- | --- |
| ボタンを押す・メニューを選ぶ | 主窓へ `WM_COMMAND` を送る |
| 数値を入れる | 入力欄へ `WM_SETTEXT` のあと Enter の `WM_KEYDOWN` を投函する |
| コンボボックスを選ぶ | `CB_SETCURSEL` のあと `CBN_SELCHANGE` を主窓へ送る |
| ファイルを読ませる | `WM_DROPFILES` を投函する（ファイル選択ダイアログを使わない） |
| 状態を読む | 入力欄・コンボ・チェックの値を `WM_GETTEXT` などで読む |
| 全体の状態を読む | pmm へ上書き保存させ、そのファイルを解析する |
| ボーン・表情のキーを打つ | vmd を組み立てて読ませる（ボーンを選択する操作が要らない） |
| 見た目を確かめる | MMD 自身の「画像ファイルに出力」でファイルに出す |

検討して採らなかった方式。

- 別デスクトップ（`CreateDesktop`）で MMD を動かす: 窓は完全に見えなくなるが、Direct3D の
  初期化が `CreateDevice Failed!` で失敗する。採れない。
- 窓を画面外へ置いて通常表示にする: 3D 画面が描画されない場合があり、利点が無い。最小化で足りる。
- MMD に DLL を読み込ませて内部を直接読む: 情報量は最大だが、ビルド環境と内部構造の解析が要り壊れやすい。
- pmm を直接書いて MMD は書き出しだけに使う: 書く側の実装が重く、途中の調整ができない。

## 3. 構成

```
mmd_cli/
  win32.py      ctypes の薄い層。MMD の知識を持たない
  ids.py        コントロール ID とメニュー ID の表（v9.32）
  dialogs.py    ダイアログの記述と分類（Win32 を呼ばない。単体試験できる）
  guard.py      ダイアログの見張り。操作を起動し、出てきた窓を隠し、応答する
  app.py        MMD の 1 インスタンスへの操作（Mmd クラス）
  scene.py      解析した pmm を、名前と度数法で読める JSON に直す
  mathutil.py   四元数とオイラー角の変換（MMD の流儀）
  formats/
    vmd.py      モーションの読み書き
    vpd.py      ポーズの読み書き
    pmm.py      プロジェクトの読み取り
  cli.py        引数の解釈と JSON 出力
tests/
  test_*.py     MMD なしで走る単体試験
  live/         実機の MMD に対する試験（環境変数で有効にする）
```

各コマンドは短命のプロセスで、MMD を見つけて 1 つ操作し、JSON を出して終わる。常駐はしない。
対象のインスタンスと作業用 pmm の場所は `%LOCALAPPDATA%/mmd-cli/state.json` に覚える。

## 4. 完了の判定

操作が終わったことを、待ち時間ではなく状態で判定する。

- 同期の操作（`WM_COMMAND`）: 別スレッドから `SendMessageTimeout` で送り、戻りを完了とみなす。
  その間、主スレッドは 1 ms 間隔でダイアログを見張る。
- 投函の操作（`WM_DROPFILES` と Enter）: 投函のあと、主窓が有効・保留ダイアログなし・`WM_NULL` の
  往復が連続 5 回成功、の 3 つが揃ったら完了とみなす。
- 後から終わる操作（画像・AVI の書き出し）: 進行表示の窓（クラス `RecWindow`）が消え、出力ファイルが
  存在することを待つ。

## 5. ダイアログの扱い

MMD のプロセスに新しい最上位の窓が現れたら、表示される前に透明化（`WS_EX_LAYERED`、不透明度 0）し、
画面外へ動かす。実測では、窓が作られてから表示されるまでの間に検出でき、表示時点で不透明度は 0 だった。
あわせて `WS_EX_NOACTIVATE` を付ける。利用者が作業中の窓を閉じた瞬間に、Windows が次のアクティブな窓として
隠したダイアログを選んでしまうのを防ぐためである（実機試験の最中に一度起き、試験の見張りが検出した）。

状態を見るだけのコマンド（`state`、`dialog list`）は、既にあるダイアログを隠さない。人が同じ MMD を手で
操作していて、そのダイアログが消えるのを避けるためである。

### 焦点の盾（guard.FocusShield）

`mmd` を走らせた端末が前面の窓のとき、`mmd` のプロセスは Windows から「前面を取る権利」を与えられていて、
MMD へ同期メッセージを送るとその権利が MMD にも渡る。すると MMD が開いたダイアログが活性化し、キーボードの
焦点が端末から MMD へ移る（通し確認で実際に起き、quit まで戻らなかった）。

対策として、各コマンドの実行中は `LockSetForegroundWindow` で前面を固定する。固定は権利を持つプロセスだけが
掛けられるので、危険があるときにだけ掛かる。利用者が ALT を押すか別の窓をクリックすると Windows が固定を解くが、
それは利用者自身の操作なので構わない。固定をすり抜けて MMD の窓が前面になった場合に備え、見張りのスレッドが
3 ms 間隔で前面を調べ、元の窓へ即座に戻す（結果の JSON に `foreground_restored` として残す）。
`Guard.run` の中でも同じ盾を使うので、ライブラリとして呼んでも守られる。

既知のダイアログは自動で応答する。

| ダイアログ | 応答 |
| --- | --- |
| モデル情報（読込時の確認） | OK。本文（モデルのコメント）は結果の JSON に入れる |
| モーションデータ読込（モデル名が違うときの確認） | OK |
| ファイルを保存する・画像ファイル出力・AVI 出力 | ファイル名を入れて保存 |
| 上書きの確認 | はい |
| AVI 出力設定 | 大きさ・fps・範囲・コーデックを入れて OK |
| 削除・新規・終了の確認 | そのコマンドが意図しているときだけ はい |

未知のダイアログは、隠したまま開いた状態で残し、題名・本文・ボタンを結果の JSON に入れてエラーにする。
`mmd dialog list` / `mmd dialog click` で人またはエージェントが応答する。
各コマンドは最初に保留中のダイアログを調べ、あれば何もせずエラーにする。

## 6. プロジェクトファイルの扱い

`dump`（全状態の読み出し）は pmm への保存を伴う。利用者のファイルを黙って書き換えないよう、
MMD のプロジェクトパスは常に作業用の写し（`%LOCALAPPDATA%/mmd-cli/sessions/` の下）を指すようにする。

- `mmd open X.pmm`: X を作業用の場所へ写し、写しを開く。
- `mmd dump`: 作業用の写しへ上書き保存して解析する。X には触れない。
- `mmd save [X.pmm]`: 作業用の写しへ上書き保存し、それを X へ写す。X を省くと開いた元の場所。
- mmd-cli を通さずに開かれたプロジェクト（利用者が手で開いたもの）に対しては、`dump` と `save` は
  既定で拒否する。`--in-place` を付けたときだけ、そのファイルへ上書き保存する。

pmm の中のモデルやアクセサリのパスは絶対パスなので、写しの置き場所が変わっても読める。

## 7. コマンド

```
mmd ps                         起動中の MMD の一覧
mmd launch [--exe P] [--pmm F] 最小化・非アクティブで起動
mmd quit [--force]             終了
mmd state                      コントロールから読める状態
mmd dump [--keys]              全状態（pmm を解析）。キーの一覧は --keys のときだけ
mmd new / open F / save [F]    プロジェクト
mmd model load F / list / select N / delete [N] / show / hide
mmd motion load F [--frame N] [--model N]
mmd pose load F [--register]
mmd wav load F
mmd accessory load F / list / get N / set N ... / delete N
mmd frame get / set N / next / prev / next-key / prev-key / first / last
mmd play [--from A --to B] [--wait] [--from-current] [--stay] [--repeat] / stop
mmd camera get / set [--pos X Y Z] [--rot X Y Z] [--distance D] [--fov F] [--perspective on|off] [--register]
mmd light get / set [--rgb R G B] [--dir X Y Z] [--register]
mmd bone list / get NAME / set NAME [--pos X Y Z] [--rot X Y Z | --quat X Y Z W] [--frame N]
mmd morph list / get NAME / set NAME VALUE [--frame N]
mmd render image OUT [--size W H]
mmd render avi OUT --from A --to B [--fps N] [--size W H] [--codec NAME]
mmd render size [W H]
mmd menu list / click ID
mmd control list / get ID / set ID VALUE / click ID
mmd dialog list / click LABEL / close / show
mmd window status / minimize
mmd file info F                vmd / vpd / pmm の中身（MMD 不要）
```

共通オプション: `--pid N`（対象のインスタンス）、`--out FILE`（JSON を UTF-8 でファイルへ）、`--timeout 秒`、
`--in-place`（mmd-cli を通さずに開かれたプロジェクトへの保存を許す）。

実装して分かり、仕様に入れたこと。

- 角度は MMD の窓に表示される値で受け渡しする。ボーンは、数学上の Y と Z の符号が逆になる
  （四元数を Y・X・Z の順のオイラー角 (10, 20, 30) から作ると、MMD は 10 / -20 / -30 と表示する）。
- カメラと照明の値は、キーとして登録しない限り、モデルを選択した時点で MMD が捨てる。
  モデルの選択中に登録なしで変更する指示はエラーにする。
- 再生の範囲は入力欄 409 / 410 だけで決まる。チェックボックス 414（フレ・スタート）は「現在のフレームから始める」、
  413（フレ・ストップ）は「止まったフレームに留まる」の意味である。再生中、フレーム番号の欄は更新されない。
- 書き出しは場面のカメラを通す（カメラ編に切り替えてから出力し、元の選択へ戻す）。
- `open` と保存の完了は、命令の戻りではなく状態（題名のパス、ファイルの更新時刻）で判定する。
  大きなプロジェクトは、命令が戻ったあとも読み込みが続くためである。
- ファイル選択ダイアログへ渡すパスは `\` 区切りに直す。`/` 区切りのままだと、ダイアログが
  「ファイル名が無効」のメッセージを自分の上に開いて止まる。

対象のインスタンスは、`--pid`、環境変数 `MMD_CLI_PID`、`mmd launch` が最後に起動したもの、
唯一起動しているもの、の順で決める。複数あって決められないときは一覧を付けてエラーにする。

## 8. 出力

- 標準出力へ JSON を 1 つ。成功は `{"ok": true, ...}`、失敗は `{"ok": false, "error": {...}}`。
- 終了コード: 0 成功 / 1 失敗 / 2 引数の誤り / 3 保留中または未知のダイアログ。
- 既定では非 ASCII を `\uXXXX` に逃がす（端末の文字コードに依らず壊れない）。
  日本語をそのまま読みたいときは `--out FILE` で UTF-8 のファイルへ出す。
- 状態を変えるコマンドは、変えたあとに読み返した値を結果に含める。

## 9. 試験

- 単体試験（MMD 不要）: vmd / vpd / pmm の読み書き、角度の変換、ダイアログの分類、引数の解釈。
  `python -m unittest discover -s tests -t .`
- 実機試験: 環境変数 `MMD_CLI_LIVE=1` と `MMD_EXE` を与えると、専用のインスタンスを最小化で起動し、
  MMD 同梱のモデル・アクセサリ・ポーズで一連の操作を行い、`state` と `dump` で結果を確かめて終了する。
  試験の間、前面の窓が MMD のものにならないこと、主窓が最小化のままであることも検査する。

## 10. ヘッドレス

- `mmd launch --headless` は主窓を非表示（`SW_HIDE`）で起動する。タスクバーにも出ない。描画と書き出しは
  非表示のままで動く（実測）。`mmd window show` で最小化状態に戻し、`mmd window hide` で再び隠す。
- `state` と `ps` に `visible` を加える。

## 11. デスクトップセッションへの中継（relay.py）

窓メッセージはウィンドウステーションを越えない。SSH ログイン・サービス・デスクトップの無いタスクは
セッション 0 の `Service-...` ウィンドウステーションで動くので、利用者のデスクトップ（セッション 1 以上、
`WinSta0`）にいる MMD を見ることも操ることもできない。また MMD 自体がデスクトップの無いセッションでは
起動を終えない（窓は作られるがコントロールが揃わず応答しない。hinata で実測）。

そこで、自分が `WinSta0` にいない（またはセッション 0 にいる）とき、`mmd` はコマンドをタスクスケジューラの
一回限りのタスク（`/IT`: 利用者がログオン中にだけ、その対話セッションで走る）として登録して実行し、結果を
受け取る。

- 引数は UTF-8 の JSON（job ファイル）で渡す。`schtasks /TR` の 261 文字制限と引用符の問題を避けるため。
- 子は `pythonw.exe -m mmd_cli --job F` として走る。コンソール窓を出さないため。`emit` は stdout が無くても動く。
- 子は開始時に `.started`、終了時に `.exit`（終了コード）を書く。親は `.started` が 15 秒以内に現れなければ
  「誰もログオンしていない」と判断してエラーにし、`.exit` を待って結果を返す。タスクと一時ファイルは必ず消す。
- `--in-user-session` で強制、`--no-relay` で禁止。`file info` のようにファイルだけを扱うコマンドは中継しない。
- `MMD_` で始まる環境変数と作業ディレクトリは子へ引き継ぐ。
- セッション 0 からの呼び出しの成功経路は、ログオン中のデスクトップがある機でしか試せない。この PC の
  対話セッションから同じ経路（タスクの登録・実行・回収・掃除）が通ることは実機試験で確かめた。
