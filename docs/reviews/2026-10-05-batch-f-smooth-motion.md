## 何を作ったか

- `tools/smooth_motion.py DANCE.vmd OUT.vmd [--report r.json] [--bones NAME ...] [--skip NAME ...] [--tension 0.5]`
  - ボーンの軌跡ごとに、キーの間（後ろのキーの曲線が 4 チャンネルとも対角線 = 直線のとき。(20,20,107,107) はこれ）を
    3 次 Hermite で置き換える。接線は両隣のキーの差分 `m_i = 2 * tension * (P_{i+1} - P_{i-1}) / (t_{i+1} - t_{i-1})`。
    tension 0.5 が Catmull-Rom（等速の直線は直線のまま）、0 で全区間 ease in/out、1 で接線 2 倍。最初と最後のキーは接線 0。
  - 回転は同じ規則を対数空間で: 区間の先頭キー q_a の体座標で `q(u) = q_a * exp(r(u))`、r は 0 から `log(q_a^-1 q_b)` への
    Hermite、端の接線は両隣の差分の回転ベクトル（先頭側の差分は q_{i-1} 座標で出るので q_a 座標へ回してから使う）。
  - 作者が曲線を付けた区間（直線でない）は元のキーと曲線から MMD の見せ方どおりに（チャンネルごとの直線補間・回転は短い方へ slerp・
    後ろのキーの曲線で ease）サンプルしてそのまま残す。
  - 軌跡の最初のキーから最後のキーまで **全フレームにキー**を書く。曲線は全部直線。キーのフレームの値は元の値そのもの
    （位置・四元数の生の値・64 バイトの 2・3 バイト目 = 物理の旗も `keep` で保つ）。
  - 触らない: 1 キーの軌跡・全キーが同じフレームの軌跡・`--skip` のボーン・`--bones` に挙げなかったボーン・モーフ・カメラ・照明・
    影・IK・モデル名。入力ファイルと OUT・--report が同じパスなら ValueError（exit 2）。書き込みは `.part` 経由。
  - 出力は 1 行の ASCII JSON（`bone_keys_before` / `bone_keys` / `bones_changed` / `segments{linear, authored}` / 全ボーンの
    `keys_before` `keys_after` `segments` `changed`）。`--report` は同じ内容を整形して書く。
- `tools/motion_jerk.py DANCE.vmd [--bones NAME ...]`（既定: センター・右腕・左腕・上半身）
  - 各ボーンの軌跡を全フレームでサンプルし、加速度の平均・99 パーセンタイル・最大を出す。センター・グルーブ・全ての親は位置の
    2 階差分 `|p(f+1) - 2p(f) + p(f-1)|`（単位/frame^2）、他は 1 フレームの回転ベクトル `w(f) = log(q(f)^-1 q(f+1))` の差
    `|w(f+1) - w(f)|`（度/frame^2）。

## 依頼の文面から外れて決めたこと

- 「直線」の判定は `(20,20,107,107)` ちょうどではなく **対角線上の曲線全部**（x1 == y1 かつ x2 == y2）。MMD はどれも直線に
  描くし、fix_twist の `sample` も同じ判定で直線にしている。
- centripetal Catmull-Rom ではなく **時間パラメータの Hermite（接線は有限差分）**。理由: 等速の直線が厳密に直線のまま（c）、
  全フレームキーの出力に再適用したときキーのフレームの値がそのまま出るので冪等（g）が厳密に成り立つ。
- 回転の C1 は **対数チャートで厳密**。角速度としては区間ごとの回転量の 2 次の分だけキーでずれる（squad も同じ性質）。
  1 軸の等速回転は厳密に等速のまま（試験あり）。
- 平均加速度は比較の物差しにしない。折れ線（キーでだけ尖る）を曲線にすると尖りが全フレームに薄く広がるので、合成の
  ジグザグでも実物でも **平均は上がる**（実物のセンター 0.039 → 0.050）。比較は p99 と最大で行う。試験もそうした。
- `--bones` に無いボーン名は無視して報告の `bones_requested_but_absent` に挙げる（ValueError にしない）。
- 報告にはすべてのボーンを載せる（触らなかったものは `keys_after == keys_before`、`changed: false`）。
- 試験で四元数の一致は **成分ごとに 1e-6（符号は別）**で見る。`angle_between`（acos）は長さ 1 - 9e-10 の格納値に対しても
  0.0068 度を返す（acos の増幅）ので、キーの保持の判定には使えない。実測して気づいた。

## 実測（この PC、`_spike/dance_original.vmd` = えぬたのダンス 39,660 キー・7,743 フレーム。`_spike/measure_real.py`、`_spike/where_spikes.py`）

- 実行時間: **5.8 秒**（読込 → 平滑化 → 書込 → 読み戻し）。出力は 512,908 キー・56.9 MB（入力 4.4 MB）。112 本のボーンを変更、
  区間は linear 39,155 / authored 331。
- 冪等: 出力に再適用して 512,908 キー全部で位置・四元数の最大偏差 **0.0**（2 回目は 16.9 秒。キー数 13 倍のぶん）。
- 全キーの保持: `RealDanceTest` が 39,660 キー全部で位置が等しく四元数が成分 1e-6 以内（符号別）を確かめる。
- 加速度（`motion_jerk`、before → after）:

| ボーン | 単位 | 平均 | p99 | 最大 |
| --- | --- | --- | --- | --- |
| センター | units/frame^2 | 0.0390 → 0.0502 | 0.5542 → 0.3611 | 1.0112 → 0.7823 |
| 右腕 | deg/frame^2 | 2.2541 → 2.7832 | 28.2088 → 22.8482 | 97.2564 → 97.2564 |
| 左腕 | deg/frame^2 | 1.9651 → 2.4455 | 25.0445 → 19.6690 | 88.2885 → 81.0686 |
| 上半身 | deg/frame^2 | 0.5960 → 0.8147 | 9.9735 → 7.4406 | 28.5000 → 26.9288 |

- 合成のジグザグ（6 キー・10 フレーム間隔）では最大が 2.0 → 0.6（3.33 倍）落ちるのに、実物の p99 は 2〜3 割しか落ちない理由を
  測った: 実物は **キーが 1〜2 フレーム間隔で連なる所**が多い（右腕は 1,689 区間のうち 507 が間隔 2 以下、中央値 3）。
  そこには間のフレームが無く、キーの値は保つ決めなので加速度はそのまま残る。右腕の最大 97.3 はフレーム 1897〜1901 に
  キーが毎フレームある所。密なキーの近傍を除いた残りのフレームでは p99 が 右腕 18.4 → 11.9、左腕 17.4 → 11.0、上半身 8.1 → 5.2、
  センター 0.51 → 0.27 と **35〜47% 落ちる**。
- 上半身の密でないフレームの最大は 21.0 → **26.9 と上がった**箇所がある。密なキーの塊の隣の長い区間で、有限差分の接線が
  長い区間には急すぎる（Catmull-Rom の知られた行き過ぎ）。`--tension` を下げれば収まるが、既定では直していない。
