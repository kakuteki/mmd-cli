`real_check.py` → `real_check.out`（実物のダンス）、`synth_check.py` → `synth_check.out`（合成の例）、`dig.py` → `dig.out`（最悪区間の掘り下げ・冪等・C1・足）、`extra.py` → `extra.out`（行き過ぎの件数・平坦区間）、`mutants.py` → `mutants.out`（試験の変異検査、写しは `mut/`）、`nonequiv.py`（生き残った変異が等価でないことの確認）。

## 結論

**このままではマージ不可（high 1 件）。** 原因は 1 つで、接線の規則（有限差分 Catmull-Rom）が「止まっているキー」を止めたままにしない。足ＩＫが床の下へ沈み（右 -0.30、左 -0.20 単位）、踏んでいる足が横に最大 0.63 単位すべり、握ったままの指が 27 度振れる。接線を直せば（止まり区間で 0・隣の弦の傾きで上限）他の medium も同時に消える。試験は回転の座標系・二重被覆・物理バイトの変異を 1 つも捕まえない。

| 重さ | 件数 |
| --- | --- |
| high | 1（H1 止まりのキーが止まらない: 足が床下・すべり・指の振れ） |
| medium | 4（M1 キーを越える行き過ぎ、M2 180 度近傍の接線、M3 定数軌跡 13 MB の無駄、M4 試験の穴） |
| low | 3（L1 物理バイトの向き、L2 浅い copy、L3 零四元数） |

## 指摘

### H1. 等しいキーが並ぶ「止まり」の区間が止まらない — 足ＩＫが床の下へ沈み、踏んだ足がすべる（high）

- どこ: `smooth_motion.py` `tangents()`。内側のキーの接線は常に `(P_{i+1} - P_{i-1}) / (t_{i+1} - t_{i-1})`。キー i-1 と i が同じ値（止まり）でも、i+1 が動いていれば接線は 0 にならず、止まっていたはずの区間 [i-1, i] が Hermite で膨らむ。
- 具体の入力と現象（合成 E、`synth_check.out`）: y=0 のキーを f0・f10、y=5 を f20、y=0 を f30。止まり区間 [0,10] の y の最小は **-0.3675（f7）**。3 キー止まり（0,10,20）でも同じ -0.3675。
- 実物（`real_check.out` / `dig.out`）:
  - 右足ＩＫ: 元の y 最小 0.0000 → 出力 **-0.3042**（f951）。元の最小より 0.05 以上低いフレームが **1,527**。等しいキーの止まり 229 のうち xz の横ずれ > 0.05 が **142**、> 0.2 が 25、最大 0.574（f2520-2576）。
  - 左足ＩＫ: y 最小 **-0.2008**（f5667）、0.05 以上低いフレーム **2,094**。止まり 220 のうち横ずれ > 0.05 が **159**、> 0.2 が 30、最大 0.626（f562-569）。
  - 原路との位置偏差: 足ＩＫで p50 0.07、p99 0.47〜0.62、最大 0.863（左足ＩＫ f2210）。
  - 回転でも同じ: 「turn 0.0」の区間（キーが等しい）で出力が最大 **27.4 度**動く（右中指３ f2815-2860、右薬指２ f4033-4100 25.9 度、左中指３ 25.6 度…、`extra.out`）。握ったままの指が区間の中で開いて戻る。
  - 全体では 39,486 区間のうち **6,016 が等しいキー同士の区間**で、その中に 263,140 フレームを焼いている。
- 証拠: 上記ファイル。記録 `docs/reviews/2026-10-05-batch-f-smooth-motion.md` も「足が床を踏む瞬間がなまる可能性は見ていない」と自認。
- 直し方（どれか）:
  1. 隣接する 2 区間のどちらかの変位が 0（位置は成分ごと・回転は角 < 1e-6）のキーは接線 0。
  2. 単調性つきの接線（Fritsch-Carlson 風）: 隣の 2 区間の傾きの符号が違えば 0、同符号なら小さい方の 3 倍（または弦の傾き）を上限。位置は成分ごと、回転は長さで。
  3. 少なくとも既定で `左足ＩＫ 右足ＩＫ` を `--skip` に入れる（ただし指と足首の振れは残る）。
- 試験に足すもの: 「等しいキー 2 つのあと動く」で止まり区間が厳密に一定であること、足ＩＫの最小 y が元を下回らないこと。

### M1. 間隔が不揃いの所で Catmull-Rom の接線が区間の弦を越える（行き過ぎ）（medium）

- どこ: 同じ `tangents()`。接線は時間で割った有限差分なので、短い区間の隣の長い区間では `dt * m` が大きくなり（例: 2.44 度/フレーム × 38 フレーム = 93 度の接線ベクトル）、横に膨らむか終点を越えて戻る。
- 実物（`extra.out` / `dig.out`、2 フレーム以上の linear 区間 37,294 本）:
  - 元の MMD 経路（slerp）からの回転の偏差: **p50 1.29 度・p99 16.7 度・最大 41.1 度**。> 10 度が 2,414 区間、> 20 度が 165 区間。
  - キーの弧を 2 度以上越える区間 **7,573**（20%）。
  - 最悪 10（度・ボーン・フレーム・区間・キー間の回転量）:
    41.07 左足ＩＫ f5855 [5852-5856] 168.8 / 37.46 右手捩 f5047 [5021-5059] 109.3 / 37.38 右足ＩＫ f3535 [3532-3537] 180.0 / 37.37 右手捩 f5046 / 37.16 右手捩 f5048 / 36.94 右手捩 f5045 / 36.65 左手捩 f4636 [4629-4638] 167.3 / 36.45 右手捩 f5049 / 36.18 右手捩 f5044 / 36.17 左手捩 f4635
  - 右手捩 [5021-5059]: キー間 109.3 度なのに出力は始点から **121.0 度**まで行って戻る。左手捩 [4629-4638]: 167.3 度に対し 174.5 度。
  - 位置: 弦の箱を 0.05 以上出る区間 944（ほぼ足ＩＫ、最大 0.626）。
  - 合成 N（密な 3 キーのあと長い区間）: tension 0.5 で 3.0 の目標に対し 3.077（2.6% 行き過ぎ）、0.25 で 3.038、0 で 3.000。
- 「数度」ではない。手捩・足首・上半身（29.2）・下半身（28.3）で 25〜41 度の寄り道がある。
- 直し方: H1 と同じ接線の上限（弦の傾きの小さい方で clamp）。tension を下げるのは全区間を鈍らせるので代わりにならない。

### M2. 隣同士が 180 度を越えて離れると接線が「近道」を取り、区間ごとの短い方（MMD の slerp）と食い違う（medium）

- どこ: `tangents()` の `log_map(relative(before, after))`。before→after の短い方を取るが、MMD は区間ごとに短い方で回る。2 区間の合計が 180 度を越えると、隣同士の短い方は逆向きの小さい回転になる。
- 具体（合成 C、`synth_check.out`）: X 軸 0 → 170 → 340 → 510 度（各区間 170 度、MMD は 170 度ずつ回る）。中央のキーの接線は **1.00 度/フレーム**（本来 17）。出力はキーごとにほぼ停止し（区間内の毎フレーム回転 4.9 … 25.4 … 4.0 度）、slerp からの偏差 17.6 度。合成 D（179 度ずつ等速）も偏差 17.3 度。
- 実物の該当: キー間の回転量が 右手捩 178.8・左手捩 179.9・右足ＩＫ/左足ＩＫ/右足首/左足首 180.0 まで達する（`real_check.out`）。M1 の最悪 10 のうち 6 本がこの範囲。
- 発散や NaN は無い（合成 B: 0→90→180→90→0 では 180 のキーの接線が 0 になり折り返す。正しい）。
- 直し方: 接線 = `rotvec(before→k)` を k の座標へ回したもの + `rotvec(k→after)`（どちらも区間ごとの短い方）、を `(t_{i+1} - t_{i-1})` で割る。区間の端で 180 度ぴったりは依然あいまい（MMD も同じ）。

### M3. 変わらない軌跡・平坦な区間まで全フレームに焼いている — 57 MB のうち約 13 MB は無駄（medium）

- どこ: `smooth()` は `keys[0].frame != keys[-1].frame` だけで判定し、`smooth_track()` は区間の中身を見ない。
- 実物（`real_check.out` / `extra.out`）: 全キーが等しい軌跡が **62 本 → 115,995 キー**（グルーブ 2→7,257、左つま先ＩＫ 2→7,743、左ダミー 2→7,743、ﾈｸﾀｲＩＫ 2→7,743 …）。両隣も等しい平坦な区間の中に焼いたフレームは **117,921 = 約 13.1 MB**（1 キー 111 バイト）。
- 合成 F: 2 キー（f0, f7000、同値）→ 7,001 キー。
- MMD の直線補間は等しいキーの間で厳密に一定なので、焼かなくても見た目は同じ。
- 直し方: (a) 全キー等しい軌跡は触らない（`changed: false`）。(b) 両端の接線が 0 で値も等しい区間は間を焼かない（出力のキーは元のキーのまま、曲線は直線）。冪等性は保たれる（1 フレーム区間に間は無い）。

### M4. 試験が捕まえない変異（medium）

`mutants.py` で `tools/smooth_motion.py` の写しに 19 の変異を入れ、`tests/test_smooth_motion.py` を走らせた（`mutants.out`。RealDanceTest は写しの場所からファイルが見えず skip）。**生き残り 10 / 19**。うち 1 つ（5b: 間のフレームに終点を含める）は `zip` が切り詰めるので等価変異で除外。実質 **9 件が穴**:

| 変異 | 結果 | 等価でない証拠（`nonequiv.py`） |
| --- | --- | --- |
| 2: 先頭側の差分を `before` の座標のまま使う（`rotate` を外す） | 生存 | 3 軸の軌跡で基準と最大 6.9 度違う |
| 2b: 回す向きを逆（before→k を k→before） | 生存 | 同上の系統 |
| 2c: `q_a * exp(r)` を `exp(r) * q_a`（世界座標）に | 生存 | **3 軸の軌跡で 93.8 度違う** |
| 3: キーの四元数を正規化して書く | 生存 | 実物では 141 キーが 1e-6 を外れ RealDanceTest で落ちる（ファイルがある機でだけ） |
| 3b: キーの物理バイトを keep しない | 生存 | 試験に (0,0) 以外の入力が無い |
| 3c: 間のフレームの物理バイトを b でなく a から | 生存 | 同上 |
| 3d: raw_name を落とす | 生存 | 試験に raw_name 付きの入力が無い |
| 9: slerp が長い方を回る（符号反転を外す） | 生存 | 格納符号が反転する軌跡が試験に無い |
| 10: relative() が長い方を取る | 生存 | 同上 |

回転の試験はすべて 1 軸（座標系が可換）なので、座標系の取り違えを一切検出しない。殺した変異: 接線の符号（位置・回転）、authored 判定（2 種）、重複フレーム、端の接線、Hermite 基底、tension の倍率、1 フレーム軌跡の素通し。
足すべき試験: 3 軸で向きが変わる軌跡を slerp 経路と比べて偏差の上限を置く／格納符号が交互に反転するキー列で等速回転が等速のまま／bytes 2,3 が非零のキーの保持／raw_name の保持／H1 の止まり区間。

注意: 変異検査の最初の回は `__pycache__` が原因で誤って 11 件「生存」を出した（同じ秒に同じバイト数で書き換えると .pyc が再利用される）。`PYTHONDONTWRITEBYTECODE=1` と削除で取り直した結果が上。

### L1. 間のフレームの物理バイト（64 バイト中 2・3 番目）は後ろのキー b から写す — 旗の意味次第で切替が 1 区間早まる（low）

- どこ: `smooth_track()`。キーのフレームは自分の `keep=a.interpolation`、間のフレームは `keep=b.interpolation`。
- 合成 I: a=(1,0)、b=(0,1)、c=(0,0) → 出力は f0 (1,0)、f1〜f10 (0,1)、f11〜f20 (0,0)。f1 の時点で b の旗になる。旗が「このキーから先の状態」なら、間は a の旗であるべき（f1〜f9 は (1,0)）。
- `vmd.bone_interpolation(curve, keep=)`（main）はバイト 2・3 だけを `keep` から写し、他は曲線で埋める。ツールの使い方はその定義と一致している。`bone_curves` は z と回転の x1 を 2 行目から読むので旗の値が曲線に化けることはない（合成 I で確認）。
- 実物の影響: 元の 39,660 キー・出力 512,908 キーともすべて (0,0)。**このダンスでは無害**。旗の意味自体は未確認（記録も推測と明記）。
- 直し方: 間は `keep=a.interpolation` にそろえる。意味が分かるまでは a と b が違う区間を報告に出す。

## 確認して問題なしだった項目

1. **キーの値の保持**（実物）: 39,660 キー全部で位置が一致、四元数は符号を除き成分 1e-6 以内。不一致 0。
2. **1 キーのボーン**: 58 本、すべて 1 キーのまま（合成 G も 1）。
3. **冪等**（実物の出力に再適用、17 秒）: キー数 512,908 のまま、位置・四元数の成分差 **0.0**。
4. **直線は直線・1 軸等速回転は等速**: 試験どおり。合成 A（格納符号が交互に反転する 0/40/80/120 度）でも f15 は 60 度ぴったり（0.0000）。
5. **二重被覆**: `relative()` と `log_map()` が短い方を取るので、格納符号の反転でキーの間に長い方を回ることは無い。出力のキーの符号は格納どおり。180 度ちょうどの隣（合成 B）は接線 0 で折り返し、発散しない。NaN は実物の全フレームで無し。
6. **authored 区間**: 元の曲線から厳密に再現（合成 H: 偏差 0.0、試験 1e-4）。
7. **`sample()`** は main の `tools/fix_twist.py` と本文が同一。
8. **C1**（実物、両隣が linear で 4 フレーム以上離れた「孤立したキー」）: キー位置の加速度 右腕 7.01 → 2.94（キーの隣 f±1 は 2.70）、上半身 3.81 → 1.45（隣 1.54）、センター 0.245 → 0.091（隣 0.089）。キーに尖りは残らない。残る大きい値は密なキー（間隔 1〜2）の所で、記録の説明どおり。
9. **VMD**: ボーン数フィールドは uint32 で 512,908、`vmd.loads` が往復、morphs 一致。
10. **motion_jerk**: 教科書のジグザグ（6 キー・10 フレーム間隔）で 最大 2.0 → 0.56、p99 も同じ、平均は 0.16 → 0.29 に上がる（記録のとおり）。回転は 6.0 → 1.68。回転は相対回転の log の差で測っており、傾いた軸の等速回転 0.000000、ピッチ 90 度を跨ぐ等速 0.000000、格納符号が交互の等速 0.000000（Euler 差分なら破綻する 3 例）。180 度ちょうどの 1 フレーム段は 360 と出る（固有のあいまいさ）。
11. 試験 18 本は worktree で全部通る（6.2 秒）。重複フレームは後勝ち（合成 L）。
