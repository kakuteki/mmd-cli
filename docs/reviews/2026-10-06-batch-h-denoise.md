## 何を作ったか

`python tools/smooth_motion.py DANCE.vmd OUT.vmd --denoise [HZ] [--denoise-cap DEG UNITS]`（既定は切。`--denoise` だけなら 7.5 Hz）。
`smooth(motion, ..., denoise=None, denoise_cap=None)` も同じ。今までの平滑（単調な C1 の Hermite で全フレームに焼く）の後に、
焼いた曲線のうち密なキーの近くだけを直す。

- 密なキー: 隣のキーとの間隔が 2 フレーム以下のキー（`DENSE_GAP = 2`）。
- 直す所（ゾーン）: 密なキーの前後 2 フレーム以内（`DENOISE_MARGIN = 2`）から、次を除いたもの。止まり（等しいキーの区間）と
  作者が曲線を付けた区間の全フレーム、止まりの直前と直後の 1 フレーム、軌跡の最初と最後のキーとその隣、密でないキー、
  高さが動く軌跡では一番低い高さのキー（床に着いた足）。
- 直し方: ゾーンごとに（前後 3 フレームは固定して）焼いた曲線 x への補正 d を
  `Σ|d|² + λ Σ|x + d の 3 階差分|²` が最小になるように取る（3 次の罰則つき最小二乗 = Whittaker 平滑、離散の最小躍度）。
  `λ = (2 sin(π·HZ/30))^-6` で、毎フレームにキーがあれば応答は `1/(1 + λ(2 sin(πf/30))^6)` の 0 位相の低域通過、HZ で半分。
  7.5 Hz では 1 フレームごとの交互の揺れ（15 Hz）が 1/9、2 フレームごと（7.5 Hz）が 1/2、4 Hz が 96.5%、2 Hz が 99.9% 残る。
- 補正はゾーンごと・チャンネルごとに平均 0・傾き 0（線形の拘束 2 本。KKT を 2×2 で解く）。走りをまとめてずらしたり傾けたりしない。
- 上限はゾーンの全フレームに: 回転は元の曲線から 3 度（回りの角）、位置は各成分 0.05（`DENOISE_CAP`、`--denoise-cap`）、
  高さはその軌跡の元の最低より下げない。はみ出したフレームを上限に固定して解き直す（最大 12 回）、最後に上限へ戻す（必ず守る）。
  回転の戻しは測地線に沿って正確に（`x·exp(t·log(x⁻¹q))`）。
- 回転は四元数の成分で均して正規化（軌跡全体で符号をそろえる）。書く四元数はそのフレームの格納の符号に合わせる。位置は成分ごと。
- 解き方: 帯幅 3 の帯行列の L D L^T（標準ライブラリだけ）。
- 報告: `report["denoise"] = {"hz", "cap_deg", "cap_units", "max_gap", "margin"}`、骨ごとに `"denoise": {"keys", "frames", "at_cap",
  "max_deg", "max_units"}`（動いたキー数・フレーム数・上限に着いたフレーム数・最大の移動）。標準出力の 1 行 JSON には合計。
- 不正な値は ValueError（終了コード 2、OUT は書かない）: HZ は 0 より大きく 15 未満、上限は正の有限の 2 数、`--denoise` なしの
  `--denoise-cap`。

## 依頼の文面から外れて決めたこと

1. **キーを動かして描き直すのではなく、焼いた曲線をフレーム単位で直す**（密なキーの前後 2 フレーム）。最初の試作
   （`h04_proto.py`: 密なキーの値を動かして Hermite で描き直す）では、走りの端のキーを動かすと隣の長い区間全体が描き直され、
   それは遅い（1.5〜5 Hz の）変化になる。取り除いた分の 6 Hz より上の割合は回転で 7%（キーの間も自由）〜14%（キーの間は固定）
   しかなかった。端のキーを固定すると 41% になるが、加速度はほとんど下がらない（右腕 p99 −12%）。上位の加速度は端と組にあるため。
   フレーム単位で直すと、補正は 2 フレームで元に戻るので局所的になる。
2. **補正の平均と傾きを 0**: 試作 2（`h08_proto2.py`、余白 3）で 6 Hz より上が回転 47% → 67%、位置 38% → 57%、加速度の下がり方は

3. **余白は 2 フレーム**（3 と 4 も測った）: 3 → 2 で 6 Hz より上が 67% → 72%（回転）、加速度は同じ。4 は 62% で利得なし。

6. **床は名前でなくその軌跡の最低の高さ**: 位置を持つ全部の骨に「元の最低より下げない」をかけるので、`右足ＩＫ`・`左足IK` など
   どの書き方でも同じ（試験は両方）。高さが動く軌跡で一番低いキー（足の接地）は動かさない。足ＩＫの密な走りの中の接地は
   右 50・左 40 キー。センターの最低（−4.8）は 2 キーで、どちらも止まりの中。
7. **上限 3 度と 0.05**: 回転 3 度は 6 度の網目の半分で、動かしたキーは（X が 0 付近なら）同じ網目の升の中に残る、つまり
   トレースと矛盾しない。位置は依頼の範囲の上端 0.05。網目の半分の 0.15 も測った: センター p99 −10.6%・最大 −30.8%
   （0.05 では −8.7%・−16.3%）。足が 1 cm 動き得るので既定は 0.05 にして、`--denoise-cap 3 0.15` で試せるようにした。
8. **遮断 7.5 Hz**: 2 フレーム間隔のキーで表せる一番高い周波数。ここより上には 2 フレーム間隔の走りの振付は無い。6.5 と 10 も測った（下）。
9. **2 フレーム間隔の交互の揺れは既定で半分**: 最初の試験では 2 倍以上と置いたが、測ると 1.96 倍で落ちた。計算し直すと、
   7.5 Hz の交互の揺れは間のフレームで 0 になる形なので間のフレームのデータは効かず、応答は定義どおり 1/(1 + 8λ) = 1/2。
   私の見積り（間のフレームの分だけ λ が 2 倍に効く → 1/3）が誤り。試験は「0.4〜0.6 倍、6.5 Hz なら 0.4 未満」に直した。
10. **次数 3（躍度）**: 人の到達運動の最小躍度モデル（Flash & Hogan 1985）と同じ量で、次数 2 より切れが良い
    （7.5 Hz で次数 2 なら 4 Hz が 90%・15 Hz が 1/5 残る。次数 3 は 96.5%・1/9）。
11. **間隔 3 は密に入れない**: 試作 2（余白 3・キー以外は自由・平均と傾き 0）で 3 まで入れると加速度はもっと下がる
    （右腕 p99 −29%・上半身 −18%・頭 −25%・センター −17%）が、6 Hz より上は回転 54%・位置 48% に落ち、1〜4 Hz が 24% / 29% に増える。
    3 フレーム間隔の交互の揺れは 5 Hz で拍の帯に入る。
12. **上限への戻しは測地線で**: `slerp` は 3.6 度未満で線形に混ぜてから正規化するので、上限ちょうどに戻らない（止めの回が尽きる
    試験で 0.000046 度はみ出した）。`exp`/`log` で正確に戻す。
13. `--denoise-cap` を出した（既定 3 度・0.05）。網目 1 つ分（6 度・0.3）にすると腕の 1 フレームの跳びが少し取れる（下）ので、
    描画を見て加賀さんが選べるように。
14. 冪等ではない: 自分の出力（全フレームにキー）にかけると全部を密とみなして均し直す（12 秒、132,863 フレームを動かした）。
    説明と README に「トレースのキーにかける」と書いた。

## 確かめていないこと

- **MMD での見た目**（描画は加賀さん側）。3 度以内の直しが目に見えて滑らかになるか、1 フレームで 100 度回る所が依然
  カクッと見えるか、60 fps の描画で違いが出るか。
- 速い所の誤差は主に時刻のずれ（どのフレームの姿勢か）と考えられるので、動きの向きに沿っては半フレーム分まで動かしてよい、
  という向きで上限を変える案は実装していない。網目 1 つ（6 度）の上限で腕の p99 が −28% まで下がるのが手掛かり。
- 3 度の上限が網目の升に収まるのは X（角度欄）が 0 付近のとき。X が大きいと Y と Z の向きが寄るので升は斜めになる。キーごとには測っていない。
- 周波数はトラック全体（動かしていないフレームは 0）の FFT（矩形窓、試験は 8192 点に 0 埋め）。区切りが短いので
  スペクトルは数 Hz 幅でにじむ。
- 平滑だけの「キーを越えない」は上限の範囲で崩れる（位置で 682 フレーム、直した後の隣の 2 キーの範囲から最大 0.10）。
- 他のダンスでは測っていない（網目の刻みが 6 度・0.3 でないトレースでは上限の根拠が変わる）。
- 物理の旗（64 バイトの 2・3 バイト目）と IK の on/off はフレームごとに平滑だけと同じ値のまま。MMD での振る舞いは未確認。
- 組み立て順 原文 → 腕補正 → `smooth_motion --denoise` → `fix_twist` は通していない（fix_twist は全フレームのキーを
  読み直すので通るはず）。
