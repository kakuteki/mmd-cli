## 指摘（欠陥と試験の穴）

### F1 カットの後の振幅ほぼ 0 の「サッカード」が数えられている（低）

- 場所: `tools/eye_gaze.py` `plan()`。原因 `cut` は振幅を見ずにサッカードを始める。
- 入力 → 出力: 実曲・生成カメラ・種 0 で、カットの前後とも目が同じ上限に張り付いている所。フレーム 261・2202・5517・5969 のカットのサッカードの振幅は 0.08・0.00・0.16・0.00 度。手持ちカメラでも 4 本（0.14・0.00・0.70・0.00 度）。
- 証拠: `t3c_cuts.py gen 256` の出力（フレーム 256 のカットの後、目は pitch -9.9 → -10.0 のまま、261 に「cut 2f amp 0.1」）。報告の `by_reason.cut` 18 のうち見える動きは 14、`in_saccade` の 8 フレームは動いていない。振幅の中央値 13.1 度にもこの 4 本が入っている。
- 直し方: 上限で止めた後の振幅が SACCADE_THRESHOLD（4 度）未満なら、サッカードにせず固視の保持点だけを今のカメラへ置き直す（数えない）。保持点の置き直しは要る（しないと古いカメラの位置を保持し続ける）。

### F2 待ちの間にカットの原因が別の原因に上書きされると消える（低）

- 場所: `plan()` の `pending = (pending[0], cause)`。docstring の「a cut stays a cause until its saccade」と食い違う。
- 入力 → 出力: 実曲のカット 1334。頭が 9 フレームで約 100 度回る最中にカット。1334 で原因 cut、1335 で PATIENCE が尽きて to_neutral に上書き、1337 にカメラが届く範囲に戻って原因が refixation に変わり、1338 に「refixation」として跳ぶ。カット 923 は to_neutral（新しいカメラが真後ろ、yaw 125 度。こちらは妥当）。
- 証拠: `t3c_cuts.py gen 1334` のフレームごとの表。同じ入力で PATIENCE だけ 12 にすると（1335 の to_neutral が起きない）、同じ 1338 のサッカードが「cut」になる。
- 影響: 動きは妥当で、ラベルと報告の原因別の数だけがずれる。
- 直し方: カットを原因とは別の旗で持ち、サッカードが始まった時に下ろす。または docstring を「to_neutral / to_camera が来ればそちらが優先」と直す。

### F3 付与の連鎖の規則に試験がない（低・試験の穴）

- 場所: `mmd_cli/fk.py` `_local()`（付与親のローカル回転＝キー × 付与親自身の付与分）。
- 入力 → 出力: 変異 X2「付与親のキーだけを使う」が 68 本すべてを通る。
- 影響: リンでは 瞳・HL・目白・グル目 の頂点が 100 % 右目子／左目子 に乗り、その親 右目補助 が 右目 を -0.5 で付与し、右目 は 両目 を 1.0 で付与する（連鎖）。規則が違えば瞳の面の傾きが変わる（瞳の位置は変わらない。I3）。この曲は 右目・左目 のキーが 0 なので fk の規則と saba の規則は同じ値になる。
- 直し方: A（キーあり）→ B（自分のキーあり、A を付与）→ C（B を付与）の鎖で、C = (キーB · A^rB)^rC を見る試験を 1 本足す。

### F4 回るだけのカット（CUT_TURN）に試験がない（低・試験の穴）

- 場所: `sights()` の `degrees_between(sight_line, previous[1]) > CUT_TURN`。
- 入力 → 出力: 変異 X3「視線の回転の判定を外す」が全試験を通る。実曲の 20 か所のカットはどれも 1 単位以上の移動で決まっていて、この判定はどこでも効いていない。
- 直し方: 距離 0 のカメラが角度だけ変える（位置が動かない）カットの試験を足す。

### F5 静止時の視線が -Z でないモデルに試験がない（低・試験の穴）

- 場所: `_seen()` の `pitch - rest[1]` と yaw の差し引き。
- 入力 → 出力: 変異 X5「rest の pitch を引かない」が全試験を通る。リンも試験用のモデルも 両目 → 両目先 が厳密に -Z なので差が出ない。
- 直し方: 両目先 を 10 度上に置いた試験用モデルで、正面のカメラに対して pitch 0 を書くことを見る。

| 中立への往復（to_neutral → to_camera） | 42 回（毎分 9.8 回）。中立にいる時間の中央値 12 フレーム、0.5 秒以下が 28 回 |
| 手持ちカメラ | どれも ±0.6 ポイント以内で同じ |

上 +10 の見え方（図 3・4）: 静止に対して、髪に隠れていない方の目（画面の左）の青い領域（瞳とまつ毛の青）が 6,058 → 5,039 画素（-17 %）。上まぶたのまつ毛の線が瞳の上側を隠す。下 -10 は 5,841 画素（-4 %）で、瞳は下へ寄るが隠れる量は小さい。画素の数え方は粗い（まつ毛の青も入る）。

### 判断

- 47.7 % は高いが、固定の 1 回は短い。長く上を見続ける問題はこの曲では起きていない（上の固定は最長 1.1 秒）。
- 見て気になりうるのは頻度の方: 上 +10（まぶたが瞳にかかる角度）に約 2.2 秒に 1 回、うなずきに合わせて上の上限と下の上限を 1 秒以内に 90 回往復、0.5 秒以下の中立への往復（大きいサッカード 2 本の組）が 28 回。
- 上の固定は、頭が下を向いた（中央値 -17 度）まま正面より上のカメラを見続ける形から来る（上目遣い）。現実的なふるまいで、問題はこのモデルでの +10 の見え方。

## 確かめられなかったこと

- 描画すべて（MMD を起動しない指示）: 60 fps の半フレーム、上限での固定・角の固定・中立への往復が動きの中でどう見えるか、R1 の +6 度でまぶたがどれだけかかるか（+10 の -17 % からの見積もりのみ）。
- MMD のカメラの回転順とチャンネル別の補間: 私の組み直しも同じ仮定を使っている。回転順はこの 2 本のカメラでは 0.02 度以内しか効かない。
- MMD の付与の連鎖の扱い（fk の規則と saba の規則）: この曲では 右目・左目 のキーが 0 なので同じ値。
- 固定軸の骨（腕捩・手捩）のキーを MMD が再生時に軸へ射影するか（motion_fk の手首だけに関係）。
- R1・R2 は一次の見積もりで、状態機械の判断（届く／届かない・待ち）への影響は回していない。
